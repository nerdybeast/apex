# CLAUDE.md

Notes for future Claude Code sessions in this repo.

## Source of truth

The design spec is **`docs/v2-spec.md`** in `nerdybeast/flutter_application_1` on branch `claude/review-strength-app-W3f8g`. That repo is reference only — APEX is a fresh project, not a migration.

When asked about behavior, schema, or naming, always defer to that spec over your own intuition.

## Repo state

This is the **scaffold**. Architecture is in place; features are not. The first task in any new session is usually to read `docs/v2-spec.md` (in the other repo) and `README.md` here, then look at:

- `lib/domain/` — freezed models for the whole domain.
- `lib/data/` — Firestore repositories, one per top-level collection.
- `lib/data/seed/` — preloaded lifts and program templates.
- `lib/core/router.dart` — go_router config and auth-driven redirect.
- `lib/features/` — one folder per screen. All but `auth/` and `onboarding/` are stubs.

## Build commands

After editing any `@freezed` class:

```bash
dart run build_runner build --delete-conflicting-outputs
```

Standard checks before committing:

```bash
flutter analyze
flutter test
```

## Conventions

- **State:** Riverpod 2.x. Providers live next to the thing they expose (repos, auth state).
- **Routing:** go_router. Add a route by editing `lib/core/router.dart` and adding a constant to `Routes`.
- **Models:** freezed + json_serializable. `DateTime` fields use `@TimestampConverter()` so they round-trip Firestore `Timestamp`. Prescription is a sealed union with `scheme` as the JSON discriminator.
- **Lints:** `prefer_single_quotes`, `require_trailing_commas`, no `print`. See `analysis_options.yaml`.
- **Firestore:** flat top-level collections, scoped by `ownerId`. No subcollections. See spec for schema.
- **Screens:** `lib/features/<name>/<name>_screen.dart`. ConsumerWidget by default; ConsumerStatefulWidget if you need controllers.

## Things that are deliberately not here

- **`firebase_options.dart`** is a stub. The user must run `flutterfire configure --project=apex-test-5ed98` locally to overwrite it.
- **Platform folders** (android/, ios/, etc.) — generated by `flutter create .` locally.
- **Generated files** (`*.freezed.dart`, `*.g.dart`) — regenerated by `build_runner`. They're not gitignored, so once generated locally they should be committed.
- **No v1 migration.** This is a fresh project against a fresh Firebase project. Don't pull anything from `nerdybeast/flutter_application_1` outside the spec.

## Build plan

Three slices, each ~2 weeks per spec:

- **Slice 1** — solo loop: onboarding, Today, session logger, e1RM auto-update against one hardcoded block.
- **Slice 2** — programs & block: lift registry seed, max management, Library with preloaded templates, start-a-block flow, block calendar.
- **Slice 3** — projection & meet: e1RM history chart, projection line, Meet attempt planner, Meet Mode, DOTS/Sinclair scoring.
